# Совместимость: iOS / iPadOS 27

**Дата:** 17.11.2026. **Собственная аппаратная проверка:** NOT RUN.

## Что установлено источниками

iMazing официально включает iOS/iPadOS 27 в поддерживаемые системы [S1]. Доступная версия для Mac — 3.6.5 от 23.09.2026 [S2, S3]. Значит утверждение «iMazing в целом не работает с iOS 27» имеющимися данными не подтверждено.

В журнале iMazing отмечены улучшение загрузки фото на iOS 27 и добавление диагностики здоровья батареи в 3.6.3. Отдельно осталась проблема скачивания приложений на **macOS 27 — системе компьютера**, а не общий сбой связи с телефоном [S2]. Это не доказывает отсутствие иных ошибок у конкретного пользователя.

В upstream issue libimobiledevice #1746 от 05.08.2026 описана потеря данных после `restore --system` на supervised-устройстве с iOS 27. Есть второе аналогичное сообщение. Полных диагностических данных, проверенного исправления и связанного PR на просмотренной странице нет. Объяснение автора о блокировке Apple — гипотеза автора, не установленный нами факт [S14]. Это сообщение **не относится автоматически к iMazing**.

Документация pymobiledevice3 описывает отдельный путь DDI/Cryptex1 для developer-сервисов iOS 27 [S17]. Нельзя переносить это изменение на MobileBackup2 без трассировки конкретной операции.

Свежая версия pymobiledevice3 **11.58.0, 17.11.2026**, добавила возможность info/list зашифрованной копии с расшифровкой Manifest.db на компьютере. Версия 11.57.1 исправила исчерпание окна приёма RemoteXPC для потока ответов. Эти изменения показывают актуальность отдельного адаптера, но сами по себе не доказывают исправление восстановления [S16]. В RR Device Desk эти версии **не включены и не проверены**.

## Разделение по операциям

| Операция | Состояние данных исследования | Решение версии 0.1 |
|---|---|---|
| USB discovery | Общий отказ iOS 27 не подтверждён | Реализован вызов idevice_id; аппаратный тест нужен |
| Pairing / trust | Общий отказ не подтверждён; ограничения доверия сохраняются | Только штатное подтверждение на устройстве, без сброса доверия автоматически |
| Wi-Fi | Зависит от ранее включённой синхронизации [S7] | Отдельный ручной режим, не обещает первичное pairing по Wi-Fi |
| Full backup | Не получен воспроизводимый общий сбой iOS 27 | Новая папка, проверки результата; только тестовое устройство на первом запуске |
| Encrypted backup | Поддержан протокольный контракт, не выполнен аппаратный тест | WillEncrypt до/после, отсутствие пароля в argv; содержимое ещё не расшифровывается |
| Restore / partial restore | Сообщение о разрушительном результате без доказанной причины [S14] | Не реализовано; никаких экспериментальных флагов на основном телефоне |
| Photos | iMazing опубликовал исправления производительности [S2] | Прямой фототранспорт ещё не реализован |
| Battery | iMazing добавил поддержку; это не гарантирует равенство сырых полей [S2] | Только реально вернувшиеся GasGauge-поля; процент здоровья не выдумывается |
| Developer services | Отдельная современная архитектура туннелей/DDI [S17] | Не требуются для базовой копии; не включаем Developer Mode автоматически |

## Что исправлено именно в нашем коде

Подтверждённый дефект внутреннего валидатора: регулярное выражение с `$` принимало UDID с завершающим переводом строки. Тест сначала упал; заменено на строгий конец `\z`. Также добавлены проверки декодирования Device, запрет NUL-путей, безопасная публикация отчётов и ограниченный хвост вывода длительной операции.

Это исправления **нашего приложения**, не заявления об исправлении iOS 27 или upstream-библиотек.

## План получения первопричины аппаратной ошибки

1. Зафиксировать модель, точный ProductVersion и BuildVersion устройства, версию macOS, Swift, libimobiledevice, тип кабеля/хаба, USB или Wi-Fi, MDM/supervision и состояние шифрования.
2. Начать с `doctor`, обнаружения и чтения сведений; отделить отсутствие устройства от отказа trust и ошибки конкретной службы.
3. На тестовом устройстве создать маленький набор собственных файлов с известными хешами. Выполнить независимую штатную копию и новую копию RR в разные папки; не запускать одновременно.
4. При сбое снять локальный код возврата и минимальный диагностический журнал нужной службы. Отключить автоматическую передачу журналов; перед публикацией проверить секреты и персональные данные вручную.
5. Повторить с тем же build и меняя только одну переменную: USB ↔ Wi-Fi, порт/кабель, состояние разблокировки, версия backend. Не очищать pairing records и не менять шифрование как «универсальное лечение».
6. Внести регрессионную фикстуру по обезличенной структуре ответа. Исправление считать технически обоснованным только после воспроизведения до/после на той же конфигурации.
7. Восстановление проверять отдельной процедурой исключительно на устройстве, потеря данных которого заранее допустима. Не смешивать обычный restore, частичное изменение backup и восстановление прошивки.

Без этих данных нельзя честно назвать первопричину конкретного сбоя Руслана. Его устройство, build iOS 27 и фактический журнал ошибки ещё не получены.

Источники [S#] раскрыты в `SOURCES.md`.
