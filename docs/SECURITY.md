# Безопасность и границы гарантий

## RR Device Desk 0.3.15, сборка 21

При выходе движок очищает память и локальный файл cookies, удаляет запись аккаунта и кэш загрузок из Keychain. Новый вход очищает предыдущую сессию до обращения к Apple. Промежуточные cookies хранятся в памяти до успешной авторизации. Обычные команды разделяют блокировку сессии, а смена пользователя требует исключительного доступа. Ошибка очистки передаётся графическому клиенту.

Движок собирается с Go 1.27.4 и закреплёнными версиями модулей. Сборочный сценарий проверяет контрольные суммы и запускает тесты всех Go-пакетов. Для публичного релиза проверяют именно движок из распакованного ZIP, подпись вложенных программ, билет нотарификации и решение Gatekeeper. Настройка подписи описана в README.

## Модель угроз

Активы: резервные копии, пароли, pairing records, файлы пользователя, состояние телефона. Недоверенные входы: путь/содержимое backup, Manifest.db, plist, ответы внешних CLI. Внешняя исполняемая зависимость доверяется только после установки из проверенного источника. База угроз не включает обещание защиты от администратора/root или полностью скомпрометированного Mac.

## Что защищено кодом

- Команды идут через Foundation.Process с массивом аргументов, не через shell. Имена утилит — enum allowlist; поиск только в явных каталогах.
- В окружение не наследуются DYLD_*, proxy, USBMUXD_SOCKET_ADDRESS или старые пароли. Только HOME/PATH/LANG/LC_ALL и, при необходимости, BACKUP_PASSWORD.
- Пароль не передаётся в argv, постоянные журналы и диагностику. Keychain только opt-in, без синхронизации iCloud. Память Swift String не гарантирует немедленное безопасное затирание — этого мы не заявляем.
- File reads: openat по компонентам, O_NOFOLLOW, только regular files, отказ от `..`, абсолютных/NUL-путей, symlink и специальных файлов.
- Manifest.db открывается read-only/immutable, SQL параметры привязаны, extensions отключены; незавершённая копия, активный WAL/journal и неизвестная схема отклоняются.
- Экспорт и новый отчёт пишутся в private temporary file, синхронизируются, затем публикуются hard link без замены существующего пути. Не поддерживающий это диск получает ошибку.
- Копирование не пишет в старую копию. Ошибка оставляет `.partial`, завершённость записывается только после проверок. Восстановление не реализовано; потенциально разрушительных команд в GUI нет.
- Свободное место проверяется до операции и во время transfer; неизвестный объём блокирует начало. Автоудаления старых копий нет.
- Внутренний журнал хранит тип операции, время и категорию ошибки. Сырой текст устройства/секреты не записываются. В UI ошибки могут содержать дополнительные поля ответа после ограниченной редактуры; не публиковать скриншоты вслепую.

## Что пока не защищено / не доказано

1. Приложение не sandboxed. Отдельного XPC worker и hardened runtime с аудитом entitlement пока нет. Внешний C backend имеет права текущего пользователя.
2. No-follow защищает компоненты внутри открытого backup, но это не полная защита от враждебного процесса того же пользователя, заменяющего предков пути/каталоги одновременно с операцией. Backup должен быть неподвижен; нельзя параллельно менять его Finder/iMazing/синхронизацией.
3. Encrypted backup reader не реализован. SHA-256 зашифрованных файлов не доказывает полноту или корректность пароля. Начальный baseline не аутентифицирует автора данных.
4. Проверка размеров/хешей из собственных файлов Apple MBFile/NSKeyedArchiver ещё не реализована; проверяем SQLite, наличие payload и собственные SHA-256. Фактическая восстановимость не проверена.
5. Файловые данные синхронизируются перед публикацией, но crash-consistency метаданных directory fsync при внезапном отключении питания не доказана. Журнал умеет обозначить неизвестное состояние, а не обещает нулевую потерю при любом сбое.
6. Большие manifests и million-file backups не испытаны; реестр/множество ID в памяти. Существуют защитные пределы разбора: plist/JSON и отдельные SQLite values 32 MiB, parsed stdout 16 MiB. Длительный backup хранит только последние 256 KiB stdout/stderr. Тайм-аут backup 24 часа; это технический safety bound, не лицензия. Профили для длительных/крупных операций требуют разработки и тестов.
7. Исходники не скачивают обновления и не имеют telemetry SDK. Политики отдельно установленного Homebrew/инструментов вне нашего процесса должны проверяться отдельно. Для предложенной установки Homebrew используется HOMEBREW_NO_ANALYTICS=1.
8. Локальные тесты не заменяют независимый penetration test. Keychain, macOS signing/launch, USB и шифрование на устройстве здесь не выполнялись.
9. Pairing/encryption UI сериализованы в одном экземпляре; межпроцессная device-lock сейчас защищает backup, но не все возможные операции другого экземпляра/сторонней программы. На первом этапе запускать один экземпляр и не использовать параллельно Finder/iMazing.
10. Диагностический журнал намеренно минимален. Полные протокольные debug traces для исследования ошибки пока не сохраняются автоматически; требуется отдельный локальный сбор с проверкой PII.

## Зависимости и распространение

Ни код, ни ресурсы iMazing не копировались. Основной backend LGPL-2.1-or-later [S8]; используемые CLI и их зависимости проверять по конкретному пакету, отдельные компоненты могут иметь иные условия. PMD GPL-3.0 ещё не встроен. Не считать эту заметку исчерпывающим юридическим заключением о будущей дистрибуции.

Перед использованием на важных данных: macOS build/tests → read-only реальная копия → тестовый телефон → independent reference backup → только затем расширение допуска. Release gate на restore сохраняется до отдельной приёмки.
