# RR Device Desk 0.3.15 — Выпуск

Приложение для macOS 13 и новее управляет библиотекой IPA, установкой приложений на iPhone и экспортом их данных. Готовый ZIP предназначен для Mac с Apple Silicon.

## Библиотека приложений (0.3.15)

1. В RR Device Desk откройте «Приложения». Готовый IPA можно импортировать сразу, без подключения телефона.
2. Для списка приложений и установки нужен внешний `ideviceinstaller` 1.2.0+ (`brew install ideviceinstaller`). Подключите iPhone по USB, нажмите «Найти iPhone», выберите устройство и при необходимости подтвердите сопряжение на телефоне.
3. Вкладка «Обзор» показывает IPA на Mac, приложения выбранного iPhone и покупки Apple Account для iPhone. Покупки и их иконки загружаются из App Store в фоне при открытии раздела «Приложения». Пока оригинал недоступен, отображается цветной значок с буквами названия. Фильтры по установке на iPhone, наличию IPA и возможности загрузки можно сочетать с поиском по названию. Для покупок при необходимости войдите в Apple Account. Выберите строки с ⌘ или Shift и нажмите «Скачать на Mac», «Установить на iPhone» или «Скачать и установить». Если Apple запрашивает лицензию, она должна быть в выбранной учётной записи.
4. Во вкладке «На iPhone» список загружается при выборе устройства. Выберите приложения с помощью ⌘ или Shift и нажмите «Скачать на Mac». RR Device Desk обрабатывает каждый пакет по очереди, используя готовый IPA той же сборки или запрашивая установленную версию по данным iPhone. При остановке готовые пакеты остаются в библиотеке.
5. Подключите целевой iPhone и выберите его. В «Библиотеке Mac» выделите IPA с помощью ⌘ или Shift и подтвердите «Установить на iPhone». Под списком появится очередь. Она показывает этап текущей установки, процент при наличии данных от iPhone и результат по каждому приложению. Ожидающие приложения можно добавить, убрать или переставить. «Пауза после текущего» даёт iPhone закончить текущую установку. При отключении подключите тот же iPhone и нажмите «Продолжить». Очередь хранится до закрытия приложения.
6. Повторная загрузка той же сборки из App Store для того же аккаунта использует существующую запись. В «Библиотека Mac» выделите одну или несколько записей и нажмите «Удалить IPA…», либо выберите это действие в контекстном меню. После подтверждения пакеты переместятся в Корзину Mac. Иконки берутся с подключённого iPhone или из сохранённых IPA.
7. Во вкладке «На iPhone» выделите приложения и нажмите «Сохранить данные…». Выберите готовую незашифрованную копию этого iPhone или создайте новую. Для новой копии нужен свободный диск и может понадобиться код на экране iPhone. Временная полная копия удаляется после экспорта. В выбранной папке остаётся по одному ZIP на приложение с `manifest.json`, локальным контейнером и доступными App Groups, заявленными установленным приложением. Экспорт использует файлы, которые iOS включила в резервную копию. Для установки приложения нужен IPA.

Если iPhone сохранил HTTPS-ссылку исходного установщика, RR Device Desk может получить IPA с того же сервера. При сохранении проверяются Bundle ID, версия и сборка. Для приложений без доступного установщика понадобится ранее сохранённый IPA. Подпись, лицензия и совместимость остаются под контролем iOS.

## Что уже написано

- Поиск USB / ранее сопряжённых Wi-Fi устройств, явный выбор устройства.
- Чтение системных сведений, сопряжение с подтверждением, запрос доступных данных батареи.
- Включение шифрования с явным подтверждением. Пароль не передаётся в аргументах команд; сохранение в локальной Связке ключей только по выбору пользователя.
- Создание новой полной локальной копии через `idevicebackup2`; проверка свободного места, отмена, отдельные частичные папки, история.
- Чтение современного незашифрованного `Manifest.db`, поиск, пагинация, экспорт оригинального файла без перезаписи.
- SHA-256 реестр и сверка, проверки SQLite и наличия файлов, защита от небезопасных путей и символических ссылок.
- Локальная диагностика и журнал операций без записи паролей и сырого содержимого телефона.

**Не реализовано:** восстановление на устройство, чтение зашифрованного содержимого, форматированный экспорт чатов/контактов/звонков/календаря, импорт на iPhone, работа с медиатекой, прямой фотобраузер. В интерфейсе это обозначено, а не изображено работающим.

## Запуск на Mac

Для сборки 21 версии 0.3.15 используется Go 1.27.4. При необходимости задайте `RR_DEVICE_DESK_GO` с путём к `go`. Сборщик проверяет SHA-256 исходного архива, контрольные суммы модулей и запускает тесты движка. Выход из Apple Account и начало нового входа очищают cookies предыдущей сессии. Параллельные операции магазина должны завершиться до смены аккаунта.

1. Распакуйте архив в отдельную рабочую папку. Не помещайте проект внутрь резервной копии.
2. Нужны инструменты Apple с **Swift 5.9+ и macOS SDK**. Проверка: `xcrun swift --version`. При отсутствии установите Xcode / Command Line Tools средствами Apple; `xcode-select --install` открывает установщик. Приложение само ничего не устанавливает.
3. Для связи с iPhone нужен Homebrew `libimobiledevice`. Установка из уже настроенного Homebrew:

```bash
HOMEBREW_NO_ANALYTICS=1 brew install libimobiledevice
```

Это отдельная, явная установка зависимости, не подписка. На дату исследования стабильная формула — 1.4.0, revision 3. Источник: https://formulae.brew.sh/formula/libimobiledevice . Не используйте `--HEAD` для первой проверки. Если Homebrew не установлен, сначала проверьте официальную инструкцию https://brew.sh/ . Не запускайте незнакомые установочные скрипты от администратора.

4. В Терминале перейдите в распакованную папку `RRDeviceDesk` и выполните:

```bash
bash scripts/build-macos.sh
```

Сборщик запускает тесты и сохраняет приложение в новой папке `dist/`. По умолчанию используется локальная ad-hoc подпись. Для распространения через Developer ID укажите идентификатор сертификата в `RR_DEVICE_DESK_SIGN_IDENTITY` и имя профиля Keychain для notarytool в `RR_DEVICE_DESK_NOTARY_PROFILE`. При заданном профиле сборщик проверяет ответ Apple, прикрепляет билет и запускает Gatekeeper.

## Первый безопасный сеанс

Сначала откройте копию **дубликата** существующей незашифрованной резервной копии: выберите папку с `Info.plist`, `Manifest.plist`, `Status.plist` и `Manifest.db`. Проверьте поиск и экспорт одного несекретного файла в новую папку APFS. Затем проверьте инструменты в разделе «Диагностика».

Для аппаратной проверки подключите **тестовый** iPhone кабелем, разблокируйте его и подтвердите доверие на экране. Выполните поиск, выберите устройство и прочитайте сведения. Wi-Fi — отдельная проверка для уже настроенной сетевой синхронизации; программа не настраивает её молча.

Создание копии требует выбранной папки, известных данных о свободном месте и шифровании, подтверждённого сопряжения и профиля CLI 1.4.0. Каждая копия новая и полная. Незашифрованная копия требует отдельного разрешения; приложение не отключает шифрование.

**Не используйте версию 0.1 как единственную защиту важных данных. Сохраните независимую рабочую копию штатным инструментом. Восстановление в этой версии не выполняется.**

## Как устроено хранение

```text
Выбранная папка/
  Backup-<UUID>/
    operation.json
    integrity.json
    data/<UDID>/Info.plist, Manifest.plist, Status.plist, Manifest.db, ...
  .partial-<UUID>/...  # неудачная / отменённая / незавершённая операция
```

Открывать в браузере копии нужно папку `data/<UDID>`. Частичные копии автоматически не удаляются. На Mac скрытые папки показывает Command + Shift + точка.

Локальный журнал: `~/Library/Application Support/RRDeviceDesk/Audit/`. Блокировки копирования: `~/.rrdevicedesk-locks/`. Пароли, pairing records и содержимое данных в диагностический экспорт не включаются. `operation.json` содержит UDID для связи истории; файл имеет закрытые права доступа и его не следует публиковать.

## Проверки и ограничения

```bash
swift test
swift build -c release --product rrdevice
# Дополнительная проверка CLI, Python 3 нужен только разработчику:
python3 scripts/cli-smoke.py "$(swift build -c release --show-bin-path)/rrdevice"
```

Пакет не скачивает Swift-зависимости. На Linux для проверки нужны SQLite/OpenSSL headers; OpenSSL не используется нашим Swift-кодом на Mac, там используется CryptoKit.

SHA-256 показывает изменение относительно собственного реестра, **не доказывает исходную полноту данных телефона и успешное восстановление**. Зашифрованная копия проверяется только как набор непрозрачных файлов. Очень крупные манифесты, работа на сетевых дисках, аварийное отключение питания и реальные iOS 27 ещё не испытаны. Экспорт использует hard link для атомарной публикации без перезаписи: выбирайте APFS; на exFAT операция может быть отклонена.
